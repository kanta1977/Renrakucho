# 設計メモ

## 方針

課題の「LINE のようなチャットアプリ」に対して、高齢の方を利用者として想定しました（docs/PERSONA.md）。
機能を増やすより、迷わずに使えることを優先し、次のことを決めました。

- 画面は「入口」「はじめの画面」「やり取りの画面」の3つにする。友達の追加も、はじめの画面の中でできるようにする
- どの画面からも「← もどる」1回で、はじめの画面に戻れるようにする
- 文字は 20px 以上、ボタンは高さ 64px 以上にする
- ログイン、メッセージなどのカタカナ語は使わず、「はじめる」「連絡」などに言い換える（パスワードだけは他に通じる言い方がないので、そのまま使っている）
- 壁紙の変更、スタンプ、既読表示、グループ作成などは作らない

既読表示を入れなかったのは、「読んだのに返事をしていない」と相手に伝わることが、負担になると考えたからです。

## 画面の流れ

```
入口 ─ はじめて使う（名前・パスワード）→ 番号の表示 ─┐
     └ 前にも使った（番号・パスワード）──────────────┴→ はじめの画面
                                                         ├ 掲示板
                                                         ├ 友達との一対一（ここから友達を外せる）
                                                         └ 友達を増やす（画面内）
```

掲示板と一対一は、同じ画面を使っています。

## お友達番号とパスワード

最初は名前だけでログインする作りにしていましたが、同じ名前の人が登録できない、他人の名前を入れるとその人として入れてしまう、という問題がありました。そこで、1人に1つ6けたの番号を発行し、名前は表示用にしました。

- 番号はランダムに作っています。連番だと、利用者の数や登録順が分かってしまうためです。
- 先頭は0にならないようにしています。
- 表示は「482-915」のように区切り、電話で伝えやすくしました。入力はハイフンや全角数字があっても受け付けます。
- 6けたで100万人分です。桁数は設定で増やせ、文字列で保存しているので、今の番号はそのまま使えます。

番号は友達に教えるものなので、番号だけでログインできると、友人なら誰でもなりすませてしまいます。そのため、ログインには番号とパスワードの両方を使うようにしました。

- パスワードは英字と数字を両方含む8〜64文字です。
- 保存するのはハッシュ値だけです（PBKDF2-HMAC-SHA256、利用者ごとに salt を付ける）。ライブラリを増やさないよう、Python の標準ライブラリで実装しました。
- 番号が違うときとパスワードが違うときで、同じ文言・同じ処理時間になるようにしました。どの番号が存在するかを調べられないようにするためです。

秘密の質問も検討しましたが、家族や知人なら答えを知っていることが多く、このアプリの使われ方では意味が薄いと考えて採用しませんでした。

## 番号を他の人に送らない

途中まで、連絡や友達一覧のデータに、相手の番号も含めて返していました。画面には出していませんでしたが、通信の中身を見れば分かる状態で、掲示板を通じて知らない人にも見えていました。

そこで、他の人の情報としては id と名前だけを返すようにし、番号は自分の分だけを返すようにしました（schemas.py の `UserOut` と `MeOut`）。同じ名前の友達がいるときは、番号の代わりに「いつ友達になったか」を表示して見分けます。

## 掲示板

最初は全員が見られる掲示板にしていましたが、知らない人の書き込みも届いてしまうため、自分と友達の書き込みだけが見えるように変えました。高齢の方を狙った勧誘などを避ける意味もあります。

特定の友達に伝えたいときのために、書くときに宛先を1人選べるようにしました。グループを作る方法も考えましたが、作る・人を入れる・外すといった画面が増えるので、宛先を選ぶ形にしました。`@名前` と入力する方式ではなく、選択肢から選ぶ形にしています。

宛先は目立たせるためのもので、書いた人の友達全員から見えます。また、友達の範囲は人によって違うので、全員が同じ書き込みを見ているわけではありません。

## DB

```
users        (id, username, friend_code, password_hash, created_at)
auth_tokens  (token, user_id, created_at)
friendships  (id, user_id, friend_id, created_at)
rooms        (id, kind, name, direct_key, created_at)
room_members (id, room_id, user_id, last_read_message_id)
messages     (id, room_id, user_id, content, mention_user_id, created_at)
```

- 友達関係は、追加したときに両方向の2行を作ります。自分の友達一覧を `user_id` だけで取れるようにするためです。
- 一対一も掲示板も rooms にまとめ、kind で区別しています。連絡の保存や取得の処理を共通にできます。
- 一対一の部屋は `direct_key`（小さい id:大きい id）に一意制約を付け、同じ2人の部屋が重複しないようにしました。
- 未読数は `room_members.last_read_message_id` より新しい連絡の数で出しています。自分の書き込みは数えません。
- 掲示板の既読位置は登録時に作ります。後から登録した人に、古い書き込みがすべて未読として出ないようにするためです。
- 友達を外しても、やり取りの記録は消しません。もう一度友達になれば元に戻ります。

## API

- はじめの画面に必要なもの（掲示板・友達・未読数・最後の連絡）は `/api/home` でまとめて返しています。
- 連絡の一覧は30件ずつで、`before_id` で前の分を取ります。OFFSET を使わないので、新しい連絡が増えても位置がずれません。
- エラーの文言はサーバー側で日本語にして返し、画面はそのまま表示します。
- 一対一の部屋は2人が友達の間だけ見られ、それ以外の人には 404 を返します。

## リアルタイム通信

- WebSocket は1人1本にして、はじめの画面の未読数と開いている会話の両方を同じ接続で更新しています。
- 一対一の連絡は2人だけに、掲示板の書き込みは書いた人とその友達だけに送ります。
- 送信は REST で行い、WebSocket は受け取るだけにしています。入力チェックや権限の確認を1か所にまとめるためです。
- 自分の送信は REST の返事と WebSocket の両方で届くので、画面側で id を見て重複を除いています。
- 切断されたら自動でつなぎ直し、その間に来た連絡を取り直します。

## 画面まわりで気をつけたこと

- 送信は「送る」ボタンだけで、Enter は改行にしました。日本語入力の変換確定で、書きかけの文が送られないようにするためです。
- 送信に失敗したときは、書いた文を消さずに残します。
- 前の連絡は自動で読み込まず、「前の連絡を見る」を押したときに表示します。
- 友達を外すときなどの確認画面では、「やめる」を左に置き、最初から選ばれた状態にしています。
- 時刻は「午後3:05」、日付は「10月17日（土）」のように表示します。
